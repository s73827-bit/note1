# 4단계: 회원권(선불 충전금) 설계

작성일: 2026-10-19 · 상태: 사용자 설계 승인 완료

## 목표

보호자별 선불 충전금을 충전·사용·환불하고, 미용 기록을 저장할 때 잔액에서 바로 차감한다.

## 사용자가 정한 것

- 종류: **선불 충전금**
- 충전: **충전 상품을 미리 등록**(예: 30만원 결제 → 33만원 충전), 직접 입력도 가능

## 데이터

`db.membership` (「백업 저장」에 포함, 없으면 빈 값):

```js
{
  products: [{ id, pay: 300000, credit: 330000 }],
  ledger: [{ id, ownerId, date: 'YYYY-MM-DD', type, amount, pay, recordId, note, at }]
}
```

- `type`: `charge`(충전, amount=+충전 금액, pay=받은 돈) / `use`(사용, amount=−차감액, recordId) / `restore`(기록 삭제로 되돌림, amount=+, recordId) / `refund`(환불, amount=−잔액에서 뺀 금액, pay=돌려준 돈) / `adjust`(조정, amount=±, note 필수)
- 잔액은 저장하지 않고 `ledger` 합으로 계산. 내역은 (date, at) 순으로 쌓아 각 줄의 잔액을 보여줌.
- 정리(normalize): 이상한 항목(id·ownerId 없음, 모르는 type, amount 숫자 아님)은 버림. 상품은 pay ≥ 0, credit > 0만.

## 규칙

- 충전금은 **보호자 단위**. 같은 보호자의 반려견이 함께 씀.
- 기록 저장 시 「충전금에서 차감」 체크(잔액 > 0일 때만 보임, 기본 체크) → `min(금액, 잔액)` 차감. 금액 > 잔액이면 "나머지 N원은 현장 결제".
- 기록 삭제 → 그 기록의 순 사용액(use − restore)만큼 `restore`. 확인창에 금액 표시.
- 반려견 삭제: 보호자가 남으면 그 반려견 기록들 사용액 `restore`. 보호자도 사라지면(마지막 반려견) 확인창에 "충전금 잔액 N원" 경고, 그 보호자 내역 삭제.
- 환불: 금액 ≤ 잔액, 돌려준 돈(기본 = 금액) 기록. 조정: 0 아닌 정수, 사유 필수, 결과 잔액 ≥ 0.
- 매출 통계는 기존대로 미용 기록 금액 기준. 「이번 달 충전 결제 금액」(그 달 charge의 pay 합)을 별도 한 줄로 표시(0이면 생략).

## 화면

- 고객 상세 「충전금」 카드: 보호자 이름·잔액, 「충전」「환불·조정」, 내역 표(날짜·내용·변동·잔액, 최신 위).
- 충전 창: 상품 라디오 + 「직접 입력」(받은 금액·충전 금액), 날짜(기본 오늘), 메모, 「잔액 A → B」 미리보기.
- 환불·조정 창: 종류(환불/조정), 금액, (환불) 돌려준 금액, 사유, 미리보기.
- 기록 폼(고객 화면·예약 완료 기록창): 「충전금에서 차감 (잔액 N원)」 체크 + 안내 한 줄. 금액이 바뀌면 안내 갱신(요금표 자동 계산 포함).
- 기록 표 금액 아래 「충전금 N원 사용」.
- 「요금표」 탭 아래 「충전 상품」 카드: 결제 금액 → 충전 금액(보너스 % 표시), 추가·삭제, 비었을 때 「예시로 채우기」(20만→21만, 30만→33만, 50만→57만). 바꾸면 바로 저장.

## 테스트 (실제 브라우저)

상품 충전·직접 입력(충전 금액 0 거부), 기록 차감·부분 차감·체크 해제, 같은 보호자 다른 반려견, 잔액 0이면 체크 없음, 기록 삭제 되돌림, 환불(잔액 초과 거부)·조정(사유 필수, 음수 잔액 거부), 마지막 반려견 삭제 경고·내역 삭제, 형제 반려견 삭제 시 되돌림, 매출 화면 충전 결제 금액, 충전 상품 카드, 예약 완료 기록창 차감, 예전 백업 normalize, 기존 67개 회귀, 390px 스크린샷.
