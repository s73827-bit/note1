# 2단계: 예약 캘린더 설계

작성일: 2026-10-19 · 상태: 사용자 설계 승인 완료, 문서 검토 대기

## 목표

미용샵(미용사 1명)이 한 주의 예약을 시간표로 보고, 예약을 등록·수정하고,
예약 상태(예정/완료/취소/노쇼)를 관리한다. 완료 처리는 미용 기록 입력으로 바로 이어진다.

## 사용자가 정한 것

- 화면 형태: **주간 시간표** (월~일 × 시간대)
- 동시 예약: **미용사 1명** → 시간이 겹치면 경고 후 사용자가 선택
- 완료 처리: 완료 시 **미용 기록 입력창**을 미리 채워서 띄움

## 기본값 (코드 상수로 변경 가능)

| 항목 | 값 |
|---|---|
| 시간표 범위 | 09:00 ~ 20:00 |
| 칸 단위 | 30분 |
| 기본 소요시간 | 90분 (30분 단위 선택, 30~300분) |

## 데이터

`db.reservations` 배열을 추가한다. 항목 형식:

```js
{
  id: 'string',
  dogId: 'string',
  date: 'YYYY-MM-DD',
  start: 'HH:MM',
  minutes: 90,
  menu: 'string',
  memo: 'string',
  status: 'scheduled' | 'done' | 'canceled' | 'noshow',
  recordId: 'string' // 완료 시 생성된 미용 기록 id, 없으면 ''
}
```

- `normalize()`가 `reservations`가 없으면 `[]`로 채운다 → 예약이 없는 예전 백업/저장 데이터도 그대로 열린다.
- `isValidData()`는 기존 3개 배열만 필수로 유지한다(예전 백업 호환).
- 잘못된 항목 정리: id 없는 예약은 버리고, 문자열 필드는 빈 값으로, `minutes`가 숫자가 아니면 90, `status`가 목록 밖이면 `scheduled`.
- 반려견 삭제 시 해당 반려견의 예약도 삭제한다. 삭제 확인창에 예약 건수를 함께 표시한다.
- 백업 JSON에는 자동 포함, CSV는 기존대로 미용 기록만.

## 화면

### 상단 탭
헤더에 「고객」「예약」 탭. 고객 탭 = 기존 화면, 예약 탭 = 주간 시간표. 마지막으로 본 탭은 기억하지 않는다(항상 고객 탭으로 시작).

### 주간 시간표 (예약 탭)
- 상단: `◀` `이번 주` `▶` 버튼과 기간 표시(예: 2026-10-19 ~ 10-25).
- 7열(월~일), 각 열 머리에 날짜·요일. 오늘 열은 강조.
- 세로축 30분 칸. 예약 블록은 시작 시간·소요시간에 맞춰 위치/높이를 잡는다.
- 블록 표시: 시작 시간, 반려견 이름, 메뉴. 색: 예정 파랑 / 완료 초록 / 노쇼 빨강 / 취소 흐린 회색(취소선).
- 같은 날 겹치는 예약은 블록을 좌우로 나눠 모두 보이게 한다.
- 시간표 범위를 벗어나는 예약(예: 08:00 시작)은 범위에 맞춰 잘라서 표시한다.
- 빈 칸 클릭 → 그 날짜·시간이 채워진 예약 등록창.
- 블록 클릭 → 예약 상세창.
- 좁은 화면(800px 이하)에서는 시간표가 가로 스크롤.

### 예약 등록/수정창
- 반려견 * : 검색 입력(이름·견종·보호자·연락처) + 결과 목록에서 선택. 반려견 상세에서 열면 미리 선택.
- 날짜 *, 시작 시간 *(30분 단위), 소요시간 *(30분 단위 select), 메뉴, 메모.
- 저장 시 같은 날짜의 다른 예약 중 상태가 `scheduled`/`done`인 것과 시간이 겹치면
  "○○(10:00~11:30)과 시간이 겹칩니다. 그래도 저장할까요?" 확인.
- 반려견 미선택 시 저장 불가 안내.

### 예약 상세창
- 날짜·시간·반려견·보호자·연락처·주의사항·메뉴·메모·상태 표시.
- 버튼: 수정, 완료, 취소, 노쇼, 예정으로 되돌리기(예정이 아닐 때), 삭제, 고객 보기.
- 「고객 보기」 → 고객 탭으로 전환하고 해당 반려견 선택.

### 완료 처리 흐름
1. 「완료」 클릭 → 미용 기록창(별도 dialog)이 열림. 방문일=예약 날짜, 메뉴=예약 메뉴로 채워짐.
2. 금액 등 입력 후 저장 → 미용 기록 생성, 예약 `status='done'`, `recordId` 기록.
3. 기록창에서 취소하면 예약은 그대로 `scheduled`.
4. 완료된 예약을 「예정으로 되돌리기」 해도 이미 생성된 미용 기록은 지우지 않는다(기록은 고객 화면에서 직접 삭제). 되돌릴 때 이 점을 확인창으로 알린다.

### 반려견 상세 연결 (고객 탭)
- 버튼 줄에 「예약 추가」 → 이 반려견이 선택된 예약 등록창(날짜 오늘, 시간 비움).
- 「다가오는 예약」 카드: 오늘 이후 `scheduled` 예약을 날짜순 표시. 항목 클릭 시 예약 탭의 해당 주로 이동 후 상세창.

## 파일

| 파일 | 변경 |
|---|---|
| `reservations.js` (신규) | 시간표 그리기, 예약 등록/수정/상세/상태 변경, 겹침 검사, 완료→기록 흐름 |
| `index.html` | 탭, 예약 탭 영역, 예약창·예약 상세창·기록창 dialog, `reservations.js` 로드 |
| `style.css` | 탭, 시간표, 예약 블록, 상태 색 |
| `app.js` | `normalize`에 reservations, 탭 전환, 반려견 삭제 시 예약 정리, 상세에 예약 추가/다가오는 예약 |

`app.js`와 `reservations.js`는 일반 `<script>`로 순서대로 로드하며 `db`, `save`, `esc`, `uid` 등 전역 함수를 공유한다. `init()`은 두 파일이 모두 로드된 뒤 실행되도록 `reservations.js` 끝에서 호출하는 대신, `app.js`의 `init()` 호출을 `DOMContentLoaded` 이후로 옮긴다.

## 오류 처리

- 저장 실패는 기존 `save()`의 알림을 그대로 사용.
- 예약이 가리키는 반려견이 없으면(데이터 손상) 블록에 "(삭제된 반려견)"으로 표시하고 상세창에서 삭제만 가능.

## 테스트 (실제 브라우저, Playwright)

1. 빈 칸 클릭으로 예약 등록 → 해당 위치에 블록 표시
2. 겹치는 시간 저장 → 확인창, 취소 시 저장 안 됨 / 확인 시 저장되고 좌우로 나눠 표시
3. 취소·노쇼 상태 변경 → 색 변경, 취소된 예약과는 겹침 경고 없음
4. 완료 → 기록창 미리 채움 → 저장 시 미용 기록 생성 + 상태 완료 / 기록창 취소 시 예정 유지
5. 주 이동(◀ ▶ 이번 주)
6. 반려견 상세의 「예약 추가」, 「다가오는 예약」 클릭 이동
7. 반려견 삭제 시 예약도 삭제
8. 예약이 없는 예전 백업 불러오기
9. 모바일 너비(390px) 스크린샷
10. 콘솔 오류 없음

## 범위 밖 (이번에 하지 않음)

예약 알림/문자, 반복 예약, 월간 보기, 미용사 여러 명, 예약 CSV.
